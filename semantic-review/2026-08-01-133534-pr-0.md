# 막대척도 결과의 반응형 페이지 이동과 6개 단위 분할

막대척도 결과 화면의 mobile/HD 상세 성향 페이지를 6개 카드 단위로 확장하고, 툴바 페이지 수를 실제 `narrowPages` 길이에 맞추는 변경이다. FHD 이상 A4 화면의 ID도 `PrintPage` 기본 계약인 `report-page-N`으로 통일해 빠른 이동과 수동 스크롤 감지가 실제 화면 페이지를 찾도록 했다. 캡처 렌더는 명시적 `bar-scale-capture-page-N` namespace를 유지한다. 검토 범위에서 기능을 막는 회귀는 발견되지 않았고 프로덕션 빌드도 완료됐다.

Watch for: **confirmed** 이 페이지 이동과 7개 이상 카드 분할을 직접 검증하는 자동화 테스트가 없어, 767/768/1279/1280px 경계의 sticky 툴바·smooth scroll 동작은 브라우저 실측이 필요하다.

## High-level view

하나의 `traitChunks` 산식이 A4와 narrow 페이지를 모두 결정한다. 7개 성향은 표지·종합 분석·상세 2장, 총 4장으로 렌더링되며 부모와 공용 뷰의 페이지 수 계약도 이 배열 길이를 따른다.

mobile/HD와 FHD 이상 화면은 모두 `report-page-N`을 사용하고 오프스크린 캡처만 `bar-scale-capture-page-N`을 사용한다. 화면 탐색과 캡처 트리의 ID namespace가 분리된다.

좁은 화면의 이동 목적지와 수동 스크롤 판정 지점은 동일한 뷰포트별 `scrollOffset`을 사용한다. mobile과 HD의 서로 다른 sticky 툴바 높이가 같은 기준에 반영된다.

### A4와 narrow가 공유하는 6개 카드 페이지 계약

`TRAITS_PER_PAGE = 6`으로 만든 `traitChunks`와 `TOTAL_PAGES = 2 + traitChunks.length`가 양쪽 렌더의 단일 원천이다. narrow는 이 수만큼 배열을 만들고 각 상세 청크를 `pages[2 + chunkIdx]`에 넣으므로 1~6개는 3장, 7~12개는 4장, 13~18개는 5장이 된다 (`frontend/src/pages/BarScaleTestResultPage.tsx:419-428,1072-1512`). 부모의 `screenPageCount`와 `DevSpectrumReportView`의 narrow 툴바도 `narrowPages.length`를 사용하고 FHD 사이드바는 같은 값인 `TOTAL_PAGES`를 받아, 표시 수와 이전·다음 clamp가 렌더된 페이지 수에 맞는다 (`frontend/src/pages/BarScaleTestResultPage.tsx:1521-1569`, `frontend/src/components/devspectrum/report/DevSpectrumReportView.tsx:112-114,208-218`).

### `report-page-N` 화면 탐색과 캡처 namespace 분리

`PrintPage`는 `id`가 없으면 `report-page-${pageNum}`을 부여하므로 공용 뷰의 narrow 렌더가 이 계약을 따른다. A4 렌더 기본 prefix도 `report-page`로 바뀌어 FHD 이상의 `scrollToPage`와 스크롤 감지기가 실제 화면 노드를 찾는다 (`frontend/src/components/common/PrintPage.tsx:178-181`, `frontend/src/pages/BarScaleTestResultPage.tsx:198-209,428`). 캡처 콜백은 계속 `renderA4Pages('bar-scale-capture-page', true)`를 호출하므로 오프스크린 노드와 화면 노드 사이에 중복 ID가 없다 (`frontend/src/pages/BarScaleTestResultPage.tsx:1565-1566`).

### mobile/HD 스크롤 오프셋과 `activePage` 동기화

빠른 이동과 수동 스크롤 checkpoint가 공통 `DEV_SPECTRUM_REPORT_NARROW.scrollOffset`—mobile 180px, HD 136px—을 사용한다. `viewport`가 effect 의존성에 포함돼 768px 경계를 넘으면 새 오프셋으로 리스너가 교체되고, 연속된 `report-page-N` DOM 수를 기준으로 `activePage`를 갱신한다 (`frontend/src/pages/BarScaleTestResultPage.tsx:185-218,1539-1550`).

### 브라우저 경계 동작의 검증 공백

**confirmed** `BarScaleTestResultPage`의 페이지 분할이나 스크롤 이동을 다루는 테스트 파일은 없으며, 이번 검증은 `git diff --check`와 `npm run build` 성공까지다. 767/768/1279/1280px에서 7개 이상 데이터를 사용해 페이지 수, 이전·다음, 직접 스크롤 후 `activePage`, PDF/이미지 캡처 장수를 확인하는 브라우저 검증이 필요하다.
