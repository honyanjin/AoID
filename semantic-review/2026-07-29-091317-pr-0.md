# 6구간 결과 리포트와 고정 A4 캡처 경로

현재 구현은 mobile/HD에서는 유동폭 3장으로, FHD 이상에서는 800×1130 A4 3장을 정비율로 보여 주며 두 결과 페이지가 같은 외곽 레이아웃을 공유한다. 요청된 11개 경계에서 화면 컨테이너, 사이드바, 페이지 footprint는 모두 가로 공간 안에 들어오고, 좁은 화면 툴바도 자체 스크롤 영역으로 버튼 초과분을 흡수한다. 확인된 문제는 넓은 화면의 가변 폭·줌 상태를 캡처 입력으로 재사용하는 점, 고정 높이 A4에서 무제한 동적 내용을 숨김 처리하는 점, 비분절 문자열의 비상 줄바꿈이 없는 점이다.

**Watch for:** **[높음 · confirmed]** FHD+ 캡처 입력 geometry가 800×1130으로 고정되지 않음; **[높음 · confirmed]** 동적 내용이 1130px을 넘으면 화면과 산출물에서 잘림; **[중간 · confirmed]** 공백 없는 긴 문자열이 mobile/HD flow 폭을 밀어냄.

## High-level view

mobile/HD 화면은 A4를 축소하지 않고 `flow` 카드로 전환한다. 320px에서 페이지 폭은 288px, border와 padding을 뺀 실내용 폭은 254px이며, 이미지와 sticky toolbar의 고정 영역은 이 폭 안에 들어온다. 툴 그룹만 `overflowX: auto`여서 버튼 초과분이 문서 전체 가로 스크롤로 번지지 않는다.

FHD 이상은 A4를 1.0/1.15/1.35/1.6배로 확대한다. 확대 footprint는 모든 경계에서 본문 열보다 작지만, **[높음 · confirmed]** 화면용 가변 root와 QHD+ 확대 상태가 그대로 캡처 입력이 되어 고정 산출물 계약을 깨뜨린다.

세 A4 페이지는 800×1130 및 `overflow: hidden`이다. **[높음 · confirmed]** 설명 세트, 추가 정보, 분포, 상세 결과에 길이 제한이나 fit 정책이 없어 최대 데이터의 하단이 사라질 수 있고, 3장째의 `fixedRatio={false}`도 동작을 바꾸지 않는다.

두 결과 페이지의 viewport 분기, 페이지 수, sidebar, capture stage는 구조적으로 대칭이다. 도메인별 게이지와 점수 스탬프 외에 한쪽에만 빠진 반응형 구간은 없다.

## 320px flow 카드와 sticky 도구 열

320px sticky Paper는 288px이다. 편집 토글과 검사 소개 버튼이 모두 있는 구성에서 고정 영역은 약 191px이고 스크롤 도구 그룹에 약 78px이 남아, 32px 아이콘 두 개와 6px gap을 표시할 수 있다. 나머지 도구는 그룹 내부 가로 스크롤로 접근한다. 높이도 약 47px로 52px 상한 안이며, HD 최소폭에서는 도구 그룹 약 484px에 라벨형 PDF 버튼까지 들어온다.

flow 이미지도 320px 실내용 254px 안에 제한된다. 대표 이미지는 `width: 100%; maxWidth: 240px`, 종합 이미지는 132px, 상세 이미지는 120px이며 모두 `objectFit: cover`다. 양 페이지의 좁은 차트 호출은 `layout="column"`과 `fluidChart`를 전달한다. `MultipleChoiceRadialChart` 내부 SVG는 검토 대상 파일이 아니어서 실제 `viewBox` 구현은 확인하지 않았지만, 호출부의 유동 모드 누락은 없다.

## 넓은 화면용 줌을 재사용하는 캡처 경로

**[높음 · confirmed]** 두 페이지는 `useOffscreen: isNarrow`이고(`TriangleTestResultPage.tsx:143-146`, `MultipleChoiceTestResultPage.tsx:160-163`), stage도 mobile/HD에서만 렌더한다(`TriangleTestResultPage.tsx:1366-1368`, `MultipleChoiceTestResultPage.tsx:1313-1315`). FHD 이상에서는 훅이 `#report-paper`를 반환한다(`ReportCaptureStage.tsx:104-107`). 이 root는 경계별 888/1028/1260/1524px이고 내부 A4는 1/1.15/1.35/1.6배다(`PrintPage.tsx:142-152`). 즉 캡처 함수에 전달되는 geometry가 FHD에서도 888px root, QHD 이상에서는 920/1080/1280px 페이지 footprint로 변한다.

후단 보정 유무와 별개로 이 계층은 “캡처 대상 DOM은 zoom 1의 800×1130”을 보장하지 않는다. 모든 구간의 저장을 800px offscreen stage로 보내고 stage `PrintPage`에 `forceZoomOne`을 명시해야 화면 zoom과 캡처 geometry가 분리된다.

mobile/HD stage는 `width/minWidth: 800px`이고 화면 밖에서 정상 레이아웃된다(`ReportCaptureStage.tsx:37-54`). 현재 좁은 구간의 fit zoom은 1이고, `capture-page-*` 접두사도 화면 `report-page-*`와 충돌하지 않는다.

## 고정 1130px 안에서 잘리는 무제한 결과 데이터

**[높음 · confirmed]** A4는 높이·최소높이·최대높이 1130px와 `overflow: hidden`을 함께 쓴다(`PrintPage.tsx:232-237`). 1px border, 32px 바깥 padding, 본문 상하 여백 후 일반 콘텐츠 공간은 약 1000px이지만 1장의 `additionalInfo`·`traitDistribution`, 2장의 `descriptionSets`, 3장의 모든 `matchedResults`를 제한 없이 렌더링한다. 항목·문자 수 예산, 실측 fit, 고정 페이지 분할이 없다.

두 페이지의 3장째 `fixedRatio={false}`(`TriangleTestResultPage.tsx:1151`, `MultipleChoiceTestResultPage.tsx:1121`)는 `PrintPage` 높이에 사용되지 않는다(`PrintPage.tsx:90, 106`). 약 1000px을 넘는 내용은 FHD+ 화면과 A4 산출물에서 사라지는 반면 mobile/HD flow에서는 보여, 화면과 저장본도 달라진다.

800×1130 3장이 절대 조건이면 관리 데이터의 최대 항목·문자 수를 판형 예산에 맞게 검증하고 최대값 fixture로 fit을 보장해야 한다. 내용 보존이 우선이면 넘친 내용을 추가 800×1130 페이지로 분할해야 한다.

## 비분절 문자열이 flow 폭을 밀어내는 경로

**[중간 · confirmed]** 320px flow 실내용은 254px이고 카드 border와 padding 후 동적 본문은 약 211px, 상세 카드 안쪽은 약 182px까지 줄어든다. 이름·별칭은 `wordBreak: keep-all`, 설명·추가 정보·결과 본문은 `whiteSpace: pre-wrap`만 사용해 비상 분절 규칙이 없다(예: `TriangleTestResultPage.tsx:256-349`, `MultipleChoiceTestResultPage.tsx:268-361`). flow는 `overflow: visible`이므로 공백 없는 긴 검사명·성향명·관리자 입력이 카드 밖으로 그려져 문서 가로 스크롤을 만들고, A4에서는 바깥 `overflow: hidden`에 잘린다.

공통 flow 콘텐츠와 동적 Typography에 `minWidth: 0`, `maxWidth: 100%`, `overflowWrap: anywhere`를 적용하고, Chip과 A4 상단 응답자 메타데이터에는 최대폭·ellipsis를 둬야 한다.

## 양 결과 페이지의 구조 대칭과 확인된 정상 항목

두 페이지 모두 `screenPageCount = 3`, 동일한 viewport 분기, sticky toolbar, capture ID 접두사, FHD+ sidebar를 사용한다. A4 주요 행은 `flexDirection="row"`이고 페이지는 `flexDirection: column`과 nowrap 기본값을 유지해 viewport 전환으로 캡처 내부 행이 세로로 무너지지 않는다.

인라인 SVG는 모두 `viewBox`를 갖고, 이미지 박스는 명시 크기와 `objectFit: cover`로 제한된다. page wrapper 간격 16/20/24/32/40/48px는 확대 A4끼리의 겹침을 막고 sidebar는 별도 flex 열이다. sidebar 카드는 `height: fit-content`라 자체 높이로 내용을 자르지 않는다. viewport 높이가 지정되지 않아 매우 낮은 화면의 sticky sidebar 전체 가시성은 이 폭 기반 검토에서 확정하지 않았다.
