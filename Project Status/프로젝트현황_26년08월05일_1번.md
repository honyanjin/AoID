## 1. 종합 요약

AoID는 독립 개발자 협회를 위한 풀스택 플랫폼으로, 단순 회원·게시판 서비스 범위를 넘어 다음 기능을 하나의 운영 시스템으로 통합하고 있다.

- 이메일/JWT/Google·GitHub OAuth 기반 회원 인증과 등급·소속·관리자 권한
- 동적 게시판, 댓글, 좋아요, 임시저장, 대표 이미지, 리치 텍스트·미디어 편집기
- 협회 소개, 주요 사업, 홈 위젯, 헤더·푸터·테마·컨테이너 폭 관리자 설정
- 회원 앱 등록과 앱 비전, 통계, 피드백, 좋아요 (마이앱 기능 — 현재 보류 중)
- 상품, 장바구니, 주문, TossPayments 결제·환불·빌링·구독
- DevCredits 잔액·원장·충전·상품 구매
- 삼각형·선다형·막대척도형 DevSpectrum 검사, 진행 저장, 제출 이력, 전체 분석과 결과 리포트
- Gemini 기반 AI 게시글·댓글 활동 스케줄러와 관리자 모니터링
- 이미지·동영상 라이브러리, 휴지통, 중복 탐지, 사용처 탐색
- 동적 sitemap과 게시글·DevSpectrum 결과 SEO 렌더링
- 별도 Markdown 뉴스 제작 서브모듈인 NewsMaker

2026-08-05 현재 핵심 애플리케이션 소스는 Frontend 484개 TypeScript 파일 139,320줄, Backend 168개 TypeScript 파일 38,205줄로 합계 652개 파일 177,525줄이다. DB 마이그레이션은 105개다. (8/1 기준 575개 파일 170,160줄 → 8/5 기준 652개 파일 177,525줄로, 컴포넌트 분할에 따른 신규 파일 증가가 반영됨)

1. **뷰포트별 컨테이너 너비 설정 시스템**: 모바일/HD/FHD/QHD/UHD/UFHD 6개 뷰포트 각각에 컨테이너 너비(px 또는 %)를 지정할 수 있는 관리자 설정 도입. 단일값 → 6구간 복제 마이그레이션, 게시판·소속(section) 단위 설정 키 확장, 홈/마이페이지/샵/장바구니 등 하드코딩 페이지 연동까지 완료.

### 3.3 백엔드 DevSpectrum 컨트롤러 팩토리 통합

`backend/src/utils/testCrudUtils.ts`(1,441줄)를 팩토리 허브로 삼아 triangle/multipleChoice/barScale 3개 컨트롤러의 반복 로직을 통합했다.

- `createCommonTest` / `updateCommonTest`: 테이블명·컬럼·태그 포맷·COALESCE 여부를 파라미터로 받는 CRUD 팩토리

- `createOverallAnalysisMatcher`: TRI/MC 빌더의 overallAnalysis 조합 매칭 블록(sequence/best_worst/pair) 추출, `includeBestWorstDescription` config으로 응답 필드 차이 보존 (BAR은 winner_combination_key 기반이라 제외 명시)
- 제출물 핸들러 팩토리(updateSubmissionPublic/deleteSubmission/getAdminSubmissions/getMySubmissions) — barScale에 없던 소유권·관리자 검증 통일

## 5. 위험 및 우선순위

### 5.1 미푸시 커밋 → 배포

루트 5 / Frontend 5 / Backend 3의 로컬 커밋이 원격에 없다. GitHub Actions 자동 배포가 트리거되므로 **push는 반드시 사용자 승인 후** 진행해야 한다. push 전에 분할 리팩토링 8종의 관리자 화면 수동 확인을 권장한다.

### 5.2 리팩토링 회귀 검증 (신규 추가)

- 분할된 컴포넌트들은 `tsc --noEmit` + CI 빌드(ESLint)로만 검증됐다. 실제 클릭 흐름(다이얼로그 열기/저장/삭제/드래그앤드롭/결제 모달)은 수동 테스트가 필요하다.
- 특히 결제 흐름이 포함된 ShopPage(구매 다이얼로그 3분기, PaymentWidget 모달, sessionStorage 복원)는 우선 검증 대상.
- 데브스펙트럼 검사 관리 3종(성향 CRUD/제출물/결과 전송)은 공통 훅 사용이 많아 관리자 검사 구성 → 결과 조회 경로를 점검할 것.

### 5.3 이전 문서에서 지속되는 항목 (8/1과 동일)

1. Toss webhook 요청 진위·재전송 멱등성 검증
2. 막대척도 비공개 결과 접근 제어와 사용자/관리자 API 계약 불일치
3. 신규 빈 DB에서 105개 JS 마이그레이션만으로 전체 스키마 재현 검증
4. 원격 URL OG 이미지 프록시의 SSRF 방어
5. `optionalAuthenticate`의 계정 활성·현재 role 재검증
6. DevSpectrum 동적 리다이렉트, 6구간 반응형 적용, 결과 판형 overflow, 선택 성향·동점 결정 규칙 정합성
7. Backend 배포 락 실패 시 해제, 동시 배포 차단, 테스트 게이트
