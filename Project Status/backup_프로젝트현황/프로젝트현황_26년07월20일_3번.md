## 4. 주요 도메인 및 기능 분석 (최신 변경사항 반영)

### 1) 종합 성향 분석(Overall Analysis) 및 최선최악(Best/Worst) 결과 관리 기능 *[최신 변경사항]*
* **데이터베이스 스키마 확장**:
  - `multiple_choice_tests` 및 `triangle_tests` 테이블에 종합 분석용 옵션인 `selected_overall_trait_ids` (JSONB)와 종합결과 표출 방식을 정하는 `overall_display_type` (VARCHAR) 컬럼이 추가되었습니다. 또한 기본 이미지(`default_overall_image_url`) 및 설명(`default_overall_description_sets`) 컬럼이 도입되었습니다.
  - 다중 성향 조합 결과를 보관하기 위해 `multiple_choice_overall_results`와 `triangle_overall_results` 테이블이 신설되었습니다.
  - 최선 성향 및 최악 성향 조합 결과를 위한 `multiple_choice_best_worst_results`와 `triangle_best_worst_results` 테이블이 신설되었습니다.
* **백엔드 관리자 API 구현**:
  - 종합 분석 설정을 불러오는 `getAdminOverallAnalysis` API를 지원합니다.
  - 성향 조합 및 최선최악 조합을 자동 생성하는 API (`generateOverallCombinations`, `generateBestWorstCombinations`)와 대량/일괄 저장 API (`saveBatchOverallResults`, `saveBatchBestWorstResults`)가 각각 추가되었습니다.
* **프론트엔드 관리자 대시보드 컴포넌트 구축**:
  - `OverallAnalysisTab.tsx` 컴포넌트가 신설되어, 관리자가 특정 성향검사의 종합 분석 표출 방식(none / sequence / best_worst 등)을 동적으로 구성하고, 조합별 설명 세트와 대표 이미지를 편집할 수 있습니다.
  - 복잡한 관리 탭 상태 관리를 위해 `useOverallAnalysis.ts` 훅이 개발되어 API 통신과 폼 데이터 동기화를 처리합니다.

### 2) 성향검사 제출 기록 고도화 및 UUID 보안 도입
* **제출 기록 UUID 추가**:
  - 제출 이력의 순차적인 숫자 ID(`submissionId`) 노출로 인한 보안 취약점을 방지하기 위해 데이터베이스 테이블(`triangle_test_submissions`, `multiple_choice_test_submissions`)에 `uuid` 칼럼을 추가하고 기존 기록에도 고유한 UUID를 일괄적으로 소급 적용하였습니다.
* **백엔드 하이브리드(Dual-mode) 조회 구현**:
  - `getSubmissionResult` API에서 정규표현식을 통해 전달받은 인자가 UUID 형태인지 감지하여, UUID 형식이면 `s.uuid = $1`로, 일반 숫자 ID 형식이면 종전처럼 `s.id = $1`로 데이터베이스를 조회하는 듀얼 모드 라우트 기능을 구축했습니다.
* **제출 및 리다이렉트 흐름 개선**:
  - 사용자가 검사를 마치고 최종 제출(`submitTest`) 시 백엔드가 UUID를 생성하여 반환하고, 프론트엔드 진행 화면(`TriangleTestPage`, `MultipleChoiceTestPage`)에서는 반환된 UUID 경로로 결과 리포트 페이지를 리다이렉트하도록 수정하여 URL 상에 원본 데이터베이스 ID가 노출되지 않도록 조치하였습니다.
* **사용자 및 관리자 UI 고유번호 표시 및 복사 기능**:
  - `TriangleTestListPage` 및 관리자 페이지(`TriangleTestManagement`, `MultipleChoiceTestManagement`)에서 각 제출 이력에 UUID를 드래그 가능한 고유번호 텍스트 박스로 렌더링하고, 원클릭 클립보드 복사 버튼을 제공하여 편의성을 높였습니다.

### 3) 삼각성향검사 성향 최고기준점(max_base_score) 설정 및 관리 기능
* **성향별 최고기준점 스키마 확장**:
  - `triangle_test_traits` 테이블에 `max_base_score` 컬럼을 기본값 100으로 신설하여 성향별로 가중할 수 있는 최고기준점 상한선을 유연하게 변경할 수 있도록 하였습니다.
* **관리자 최고기준점 편집 기능**:
  - 관리자 화면인 `TriangleTestManagement.tsx` 컴포넌트에서 각 문항 성향을 일괄 관리하고 수정할 때 최고기준점을 입력/수정할 수 있도록 UI를 확장하고 이를 백엔드 수정 API(`saveTraitsBatch`)와 통신하도록 동기화했습니다.

### 4) 결과지 보고서 인쇄 디자인 및 시각화 도구 개선
* **삼각성향검사 방사형 차트 도입**:
  - `TriangleTestResultPage.tsx`에 방사형 차트 컴포넌트(`MultipleChoiceRadialChart`)를 2페이지(종합 성향 분석)로 신설 탑재하여 결과 리포트의 완성도를 높였습니다. 이로써 인쇄용 리포트 구조가 2페이지에서 3페이지 구조로 확대 개편되었습니다.
* **인쇄용 가독성 및 디자인 통일**:
  - `PrintPage` 각 구획 하단에 검은색 얇은 구분선(`Divider`)을 명시하여 웹 브라우저에서 인쇄할 때 구역 구분이 뚜렷하게 나뉘도록 디자인을 가다듬었습니다.
  - 성향을 수치적으로 나타내는 뱃지의 칩 배경색을 하드코딩된 단색(indigo)에서 각 성향 고유의 매핑 컬러(`RADIAL_PALETTE`)로 동적으로 표시하여 시각적 다양성을 확보했습니다.

## 5. 이전 발견된 런타임 오류 및 버그 해결 현황 (Bug Fixes)

### 1) UUID 기반 결과 조회 시 프론트엔드 NaN 변환 오류
* **문제 상황**:
  - URL 파라미터로 UUID 문자열이 넘어왔을 때 `parseInt(submissionId, 10)`을 수행하여 `NaN`이 발생하였고, 이 값이 API에 그대로 전달되어 결과 화면이 렌더링되지 않던 치명적 런타임 에러가 보고되었습니다.
* **해결 완료**:
  - 프론트엔드 결과 조회 페이지 [TriangleTestResultPage.tsx](file:///c:/Project/AoID/frontend/src/pages/TriangleTestResultPage.tsx#L41) 및 [MultipleChoiceTestResultPage.tsx](file:///c:/Project/AoID/frontend/src/pages/MultipleChoiceTestResultPage.tsx#L55)의 진입부에서 `submissionId`가 숫자로만 구성되어 있는지 정규식(`^\d+$`)으로 사전 검사하도록 수정하였습니다.
  - 숫자인 경우에만 `parseInt`를 적용하고, UUID 형식 문자열인 경우 원본 문자열을 그대로 `subId`에 담아 API 서비스 훅으로 넘겨주어 하이브리드 조회가 정상 동작하도록 수정되었습니다.
  - 프론트엔드 API 서비스 파일들(`triangleTestApi.ts`, `multipleChoiceTestApi.ts`) 내 `getSubmissionResult` 인자 타입이 `submissionId: number | string`으로 안정적으로 넓혀진 것을 확인했습니다.
