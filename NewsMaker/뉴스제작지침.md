[조사주제]
별다른 지시사항이 없을경우 : 주요 AI 모델들의 업데이트, 개발자가 관심가질만한 이슈, 코딩관련.
사용자의 특별한 조사주제 지시사항이 있을 경우는 그 주제를 조사할 것. 

[핵심주의사항]
실제로 오래 전에 발표한 사항이거나 사용자가 지시한 기간에 이슈가 된 사건이 아닌데도 불구하고 최신뉴스로 오인하고 사용자가 지정한 기간 내에 일어난 사건으로 오인하여 뉴스를 선정하는 경우가 아주 많이 발생중이다. 이를 철저하게 감별하도록 주의하여야 한다. 

[중복된뉴스검토]
뉴스 목록을 작성한 후에 NewsList_Done.md 파일을 참조하여 중복된 뉴스는 제거할 것.
단, 주제는 중복으로 보이지만 뉴스 내용이 이전 뉴스와 크게 달라져서 업데이트가 필요한 뉴스라면 사용자에게 (사용자의 업데이트 검토 필요) 표시를 한 후에 목록에 포함할 것.
이후 사용자의 제외지시가 있으면 제외표시를 하고 그 기사는 작성을 하지 않는다. 
별다른 제외지시가 없으면 기존 새로운 기사로 작성하되, 기존 기사 정보(작성날짜와 기사제목)를 기사 하단에 별도로 추가한다.

[뉴스개수결정]
우선 다양한 이슈를 목록화한 다음에 중요도 순으로 나열한 후에 별 6개 이상인 뉴스는 모두 개수에 포함한다. 
목록작성시에는 최소 카테고리별로 10개의 뉴스는 제작한다.
제작된 뉴스의 개수가 카테고리별로 10개 미만으로 부족하다면 별이 낮은 것도 포함한다.
중요도가 높은 뉴스가 많아서 제작해야할 뉴스가 수십개가 된다면, 작업물의 결과가 최선이 되도록 목록을 나누어서 여러차례 나누어서 작업을 진행하라.
사용자 특별지시사항으로 단독주제 1개에 대한 특집기사를 작성해야한다면 그 주제 1개에 대해서 특집기사를 작성하라.

[필수작성사항]
A. 타이틀
B. 중요도 (별1 ~10까지)
C. 카테고리
D. 뉴스 내용에 해당되는 해시태그들
E. 각 뉴스마다 대표적으로 사용할 수 있는 연관 이미지 
F. 부제
G. 기사본문 
H. 뉴스를 작성한 자료들의 출처

[카테고리현황]
- 새소식(IT일반)
- 새소식(AI)
- 새소식(Code)

[뉴스파일작성지침]
형식은 MD 형식으로 작성한다.
목록화한 리스트 파일은 1개에 모두 작성한다.
뉴스파일은 카테고리별로 각각 작성한다.
단독주제 1개에 대한 기사를 작성할때는 리스트 파일은 필요하지 않다.

[파일명명규칙]
목록파일명은 여러 날짜를 지정한 경우에 NewsList_YYYYMMDD_to_YYYYMMDD.md 형식으로 작성한다.
단일 날짜를 지정한 경우에 NewsList_YYYYMMDD.md 형식으로 작성한다.
카테고리별 뉴스파일명은 여러 날짜를 지정한 경우에 News_YYYYMMDD_to_YYYYMMDD_카테고리명.md 
단일 날짜를 지정한 경우에 News_YYYYMMDD_카테고리명.md 형식으로 작성한다.
특별기사파일명은 Special_YYYYMMDD_주제명.md 형식으로 작성한다.
주제명은 뉴스본문의 핵심키워드를 주제명으로 한다.
주제명에 공백이 포함되어 있다면 언더스코어로 대체한다.

[중요규칙]
답변 양식을 반드시 통일할 것.
뉴스마다 필수작성사항의 순번을 반드시 지켜서 작성할 것.
지시하지 않은 추가 양식이나 불필요하게 여러 뉴스를 섞어서 작성하지 말 것.
뉴스가 어느 카테고리에 속하는지 카테고리현황에서 카테고리 1개 선택하되, 어느 카테고리에도 속하지 않는다면 새소식(IT일반)으로 하되, 추천카테고리를 추가로 하나 더 기재할 것.
단독주제인 경우에 매우 세심하고 디테일하게 내용을 조사해야한다.

[본문글작성양식규칙]
마침표 다음은 반드시 줄바꿈을 할 것.
행간 간격은 기본적으로 1.2로 한다. 단락을 나눌 경우에 빈줄을 추가해도 되지만 행간 간격은 1.2로 유지한다.
기사 본문에 불필요한 들여쓰기와 공백을 쓰지 말 것.
본문 내 소제목에 숫자 넘버링은 사용자의 직접적인 지시가 없으면 붙이지 말 것.

[작성지침]
조사한 뉴스가 실제로 기간 내에 일어난 사건인지 반드시 면밀하게 재확인할 것.
이전에 일어난 일을 기간내에 다시 뉴스로 내보내는 사례를 주의할 것.
조사한 뉴스에 대해 실제로 자료조사를 실시하여 팩트를 면밀하게 체크할 것.
태그들은 뉴스 본문의 내용을 잘 생각해서 태그들을 나열하고 그중에 대표적인 태그 1개를 골라서 대표 태그로 표시할 것. 
뉴스는 명확하게 [뉴스1] ~ [뉴스N]까지 명확하게 번호를 붙여 작성하고 뉴스와 뉴스 사이에 구분선 넣어줄 것.

[본문작성분량]
본문은 가능하면 2000자 정도로 작성할 것.
단, 단독주제 1개에 대한 특별기사를 작성한다면 최소 10000자 정도는 작성할 것.

[이미지조사지침]
연관 이미지는 반드시 최소 1개는 찾아줄 것.
직접 이미지를 그리라는 것이 아니라 연관된 이미지를 찾아서 표시할 것.
각 이미지마다 조사한 자료의 출처를 표시할 것.
이미지는 본문에 핵심적으로 등장하는 회사와 관련된 이미지를 찾을 것.
이미지는 출처에서 관련된 이미지를 찾을 것.
이미지를 unsplash에서 찾는 것은 최후의 가장 마지막 수단으로 할 것.
이미지 주소를 실제로 접속시에 "File not found:" 으로 시작한다면 제대로 된 이미지가 아니므로 이미지 주소는 반드시 본문에 직접 클릭시에 접속가능한 이미지이어야 한다.

[이미지생성프롬프트작성]
각 뉴스 본문에 들어갈 대표이미지 프롬프트 1개와 본문내용에 어울리는 이미지 제작용 프롬프트 3개 작성해줄 것.
이미지에 들어가는 글자는 가능한 한국어로 작성되어야 함을 프롬프트에 포함할 것.
이미지는 너무 복잡한 이미지가 아닌 인포그래픽 스타일의 깔끔한 이미지이어야 한다는 점을 프롬프트에 포함할 것.
이미지 좌상단에는 항상 AoID.kr 문구가 포함되어야 한다는 점을 프롬프트에 포함할 것.
작성된 프롬프트는 기사작성시 이미지목록의 바로 하단에 별도로 명시할 것.  

[출처표기지침]
- 뉴스 작성에 사용한 모든 자료들의 출처 주소들은 목록화하여 뉴스마다 하단에 정리해둘 것.
- 출처의 주소는 md 파일에서 직접 클릭이 가능해야함.
- 출처는 대표주소만 적는 것이 아니라, 실제로 해당 내용을 언급하고 있는 웹 페이지의 주소까지 추가로 모두 작성할 것.

[기타지침]
특정 커뮤니티의 사용자 반응을 가져올 때, 그 커뮤니티의 이름을 직접 가져와서 본문에 넣지 말 것. 아예 이름을 배제하고 대명사로 작성할 것. 예를 들어 커뮤니티의 이름을 언급하는 것은 제외하고, '한 개발자 커뮤니티', '한 유저들의 반응에 따르면' 등으로 대치하여 작성할 것.

[파일저장경로]
- /NewsMaker/News_Detail : 카테고리별 뉴스 파일 
- /NewsMaker/News_Special : 특집기사 파일
- /NewsMaker/News_List : 리스트 파일
- /NewsMaker/News_List_Done : 뉴스 작성 완료 리스트 파일

[뉴스제작단계]
- Step1 조사주제에 대한 뉴스 목록화 -> News_List에 목록 저장. 
- Step2 목록의 내용이 실제 기간내에 적합한 뉴스인지 심층적으로 검토 -> 이미 예전에 일어난 일을 다시 뉴스로 내보내는 사례나 블로그에 올리는 과거의 이슈를 철저하게 검토해서 제외.
- Step3 사용자의 목록 검토 및 최종승인 -> 수정할 것이 있다면 수정후 다시 목록화 후 최종승인. 
- Step4 뉴스작성 -> News_Detail에 뉴스 기사 저장.
- Step5 사용자의 기사 검토 및 완료통보 -> 수정할 것이 있다면 수정 후 완료통보. 
- Step6 완료 리스트 업데이트 -> 사용자가 완료통보한 기사들은 News_List_Done 폴더의 NewsList_Done.md에 업데이트
